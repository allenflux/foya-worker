# AIAPI 日统计管理台

Java 21 网页后台，通过 **p0 只读 GET 接口**统计成功任务，在网页配置 Telegram 机器人并定时发送日报。不连接业务数据库；配置、每日汇总和发送记录都保存在文件中。

## Docker Compose 部署

```sh
test -f .env || cp .env.example .env
docker compose up -d --build
```

打开 `http://服务器IP:8080` 即可使用，无需登录或密码。端口可通过 `FOYA_PORT` 修改；绑定地址由 `FOYA_HTTP_BIND` 控制，默认 `0.0.0.0`。

在网页中完成：

1. **机器人配置 → P0 数据源**：接口默认是 `https://p0-function.inaiai.com/api/tasks/list`。API Key 可留空测试匿名访问；需要鉴权时在此填写。选择接口实际要求的时间参数格式，默认 `yyyy-MM-dd HH:mm:ss`，也支持 Unix 秒/毫秒。统计时区默认 `Asia/Shanghai`。
2. **Telegram 机器人**：可添加多个机器人，各自填写名称和 Bot Token、设置启停。默认“自动登记群组和私聊”，无需手填 Chat ID：将机器人加入群组会登记该群，私聊用户先发 `/start`（或任意首次消息）即可登记，`/stop` 取消接收，退群也会取消。可从 Telegram 的 @BotFather 创建机器人。每个机器人的“高级”选项可设置手动 Chat ID、话题 ID 和独立发送时间（留空沿用全局时间）。测试连接调用只读 `getMe`，不会发送消息。
3. **渠道与工作流**：导入已有的 `hash2channel.json`，格式为 `{"hash_key": "渠道名"}`。工作流映射格式为 `{"task_type": "工作流名"}`。不提供默认的虚构映射；未映射的非空标识显示原值，空渠道显示“未分類”。保存映射后无需重新拉取。当前金额暂不统计，后续再接入独立的 `task_type → 单价` JSON 映射，按单数乘单价计算；该单价映射目前尚未实现。
4. **统计概览**：点击“刷新统计”，首次补齐所选结束日之前 10 天的缺失缓存。可选择历史结束日；仅支持完整日期，最晚昨天。预览确认后可“立即发送当前报表”，选择全部启用的机器人或其中一个，无需等待定时任务，关闭自动推送也可手动发。
5. **AI 数据总结**：默认 Base URL 为 `https://llm.aiaipool.com/v1`，模型为 `deepseek-v41-flash`。在网页填写 Key 或使用私有 `.env` 的 `LLM_API_KEY`，可设置是否附加总结以及总超时（默认 20 秒）。只把每日汇总、最新日渠道和工作流 TOP10 交给模型；原始任务、p0 Key 和 Telegram Token 不会传给模型。
6. **日报计划**：设置“日报与 AI 总结发送时间”、报表天数（默认 10，可选 1–31）并开启自动推送。统计和总结按照同一个时间每天发送，默认北京时间；机器人可单独覆盖时间。**保存配置后生效**；若开启时当天发送时刻已过，将补执行昨天的日报。一个接收目标发送失败，不影响其余机器人和群继续发送。

页面的 CSS 和组件 JS 使用 Bootstrap **5.3.8 CDN**，自定义 CSS 仅保留少量辅助样式，业务 JS 负责请求接口与展示真实数据；无需 Node 或前端构建步骤。部署浏览器需要能访问 `cdn.jsdelivr.net`。

配置、缓存和发送状态使用 Compose 的 `aiapi-data` 命名卷，重建容器或 `docker compose down` 后仍保留。`docker compose down -v` 会删除这个卷及其中数据。

```sh
docker compose ps
docker compose logs --tail=100 -f
# 更新部署
docker compose up -d --build
```

## 统计口径

- 请求仅为 `GET /api/tasks/list`，参数为 `status=2&start_time=…&end_time=…&page=…&page_size=1000`，始终带 `canary: true`，配置了密钥才带 `apikey`。
- 每页请求默认最多尝试 **50 次（含首次）**，网页可改为 1–50 次。网络故障、超时、HTTP 408/429 和 5xx 使用 1、2、4、8、16、30 秒指数退避，之后每次最多间隔 30 秒；尊重服务端 `Retry-After`（超过 5 分钟则停止当前轮次，交由后续定时重试）。401/403 等鉴权错误、业务错误或字段结构异常会明确报错，等待修正配置。重试只针对失败页，不把已成功页面重复累加。
- 北京时间每天切成 24 个小时段，最多 6 个并发，各小时独立分页。请求次数取决于记录数及接口返回的分页信息，不承诺固定 70 次或固定耗时。
- 按原始 `hash_key × task_type` 累计单数。当前默认只统计单数，所有金额显示“未统计”，渠道按单数排名；不依赖 `fee` 生成日报。缺失、null 或无效的 `fee` 均不丢弃任务、不阻止缓存和发送。缓存仍保存已知金额小计和缺失金额单数，供后续核对使用，不会把小计误当完整金额展示。
- 按任务创建时间校验半开区间 `[当天00:00, 次日00:00)`，按任务 ID 去重，防止小时边界重复计数。任务缺少可解析创建时间时拒绝生成缓存，避免错算跨日记录。
- 每日 JSON 仅含汇总和元数据。全部小时成功、分页完整才原子写入；某小时失败不会覆盖已有完整缓存。数据源地址、密钥、时区或时间参数格式变化会使旧缓存失效；仅改名称映射不会失效。
- 适配的任务数组包括 `data.list/tasks/items/records/rows`、`data` 数组及顶层数组；任务需有 `hash_key`、`task_type` 和可解析的创建时间（也兼容已实现的别名），`fee` 是可选信息。分页支持 `total`、`has_more` 等；若没有分页元数据，继续取页直到空页，避免服务端暗中缩小页长导致漏数。业务错误、必需字段异常、重复页和矛盾分页信息会停止统计。
- 每日行按日期倒序。当前渠道及工作流 TOP10 均按最后一天单数排名，占比以该天总单数为分母，显示其余渠道/工作流合计。
- 后续正常定时运行只需拉取昨天一天，之前 9 天直接复用缓存。缺历史缓存时自动补齐，报表不完整不发送。

报表发送为纯文本，不设置 Markdown 解析模式，因此渠道名中的下划线、标点不会破坏消息格式。超过 Telegram 长度限制时按行拆分。详见 [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)。

AI 总结成功时在原统计后附加 `【AI 数据总结】`。模型最多尝试两次，所有请求共用配置的总超时；网络异常、HTTP 错误、空响应或超时一律回退为原始统计报表，**不会影响 Telegram 发送**。网页可先生成总结并预览，相同报表与模型配置会短期复用总结，避免重复调用。LLM 提供解读，不修改统计数字，也不会编造未统计的金额。

网页报错会在“错误详情”区域持续显示，包含出错步骤、时间、状态码、请求编号和脱敏原因，可一键复制给开发排查。复制内容不包含请求正文、上游原始响应、任务数据或密钥；异步拉取/发送失败也会显示同样的详情。

## 密钥及现有脚本复用

网页保存的密钥在数据卷内的 `config.json`，目录权限 `0700`、文件权限 `0600`。GET 配置接口和非敏感配置导出不返回密钥；密钥输入框留空表示保留已有值。日志不会输出密钥、原始响应或任务内容。后台无需登录，服务 API Key 和 Bot Token 仍用于连接各自的上游接口。

需要复用外部配置时，在 Compose 中增加只读挂载，然后在网页填写容器内文件路径：

```yaml
services:
  aiapi-stat:
    volumes:
      - aiapi-data:/app/data
      - /your/existing/p0-config.json:/run/secrets/p0-config.json:ro
```

支持纯密钥文本、JSON 顶层字段 `apikey` / `api_key` / `p0ApiKey` / `P0_API_KEY` / `APIKEY`，或包含这些变量的 `.env`。不执行盯盘脚本、不读取其它渠道 apikey；复用文件时不会把密钥复制到配置文件中。容器的非 root 用户须能读取挂载文件。

也可通过进程环境 `P0_API_KEY`、`P0_API_KEY_FILE`、`TELEGRAM_BOT_TOKEN`、`LLM_API_KEY` 提供密钥；环境值优先于网页配置。Compose 已支持从 `.env` 注入 `LLM_API_KEY`；其它环境项按需加入 `environment`。网页中的“清除已保存密钥”不会清除环境变量，请同时在部署配置中删除对应环境值。

## 发送与失败恢复

自动登记使用 Telegram `getUpdates`，每 15 秒同步一次，仅保存接收会话 ID/名称、更新偏移与 Token 哈希，不保存聊天正文或 Token。首次使用请在后台保存机器人后再加群或私聊 `/start`。对于已有群可在群中发 `/start` 或 `/subscribe` 登记。频道可在高级选项手动填写 `@频道用户名`，并给机器人发送权限。

已有 Webhook 的机器人会跳过轮询并记录提示，不会擅自删除 Webhook；也不要让其它应用同时消费同一个机器人的 `getUpdates`，否则更新可能被其它应用取走。此时可使用专用日报机器人，或改用手动 Chat ID。机器人更换 Token 后需重新登记，旧 Token 的会话不会误用到新机器人。

定时发送前先持久化发送记录，同一统计日、机器人和接收目标不会因重启再次自动投递。每个接收目标独立记录状态与重试时刻，不会影响其它机器人按时发送。p0 拉取失败会在 5 分钟后重试，当前进程当天最多 3 次；已成功拉取的日缓存继续复用。发送失败、超时、部分分段成功或重启时处于发送中状态，统一标记为待人工核对，不自动重发，避免重复消息。核对 Telegram 后可手动点击发送。

手动发送是显式重发操作；重复点击会生成重复消息，请留意。服务应单实例运行，不要让多个实例共享同一数据卷。

## 本地开发与验证

```sh
mvn test
mvn package
java -jar target/foya-worker-1.0.0.jar
```

本地默认监听 `127.0.0.1:8080`，Docker 监听 `0.0.0.0:8080`，均无需登录或密码。其它环境项：`PORT`、`FOYA_BIND`、`FOYA_DATA_DIR`（本地默认 `./data`）。

自动测试使用本机模拟 p0、LLM 和 Telegram HTTP 服务，验证 50 次重试、分页、时间边界、金额精度、缓存失效/保留、报表排序及其它项、免登录访问、请求保护、配置脱敏、LLM 超时和失败回退与 Telegram 分段/限流/发送失败，不发送真实消息。

**真实接口联调状态**：最新匿名只读探测已返回 HTTP 200，但任务数组为空（测试了日期时间、Unix 秒和毫秒格式），尚未获得带真实任务的数据来核对剩余必需字段。部署后先在网页测试 p0；有真实响应后若必需字段结构超出支持范围，系统会显示脱敏错误详情；缺少 `fee` 不再导致报错。现有的 322 个渠道映射文件未在这台机器上找到，需要在网页导入。

使用实际 Java 服务端、提供的 LLM 地址和模型完成了真实连接测试，已成功获得模型响应；连接测试未发送任何业务统计。真实凭据只保存在 Git 忽略的私有 `.env` 中，没有写入源码、前端或文档。
