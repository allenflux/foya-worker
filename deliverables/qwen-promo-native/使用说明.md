# Qwen 2.1 宣传图 · 原生节点版

直接导入 `Qwen2.1_宣传图_原生节点版.json`，无需安装上一版新增的自定义节点。

1. ① `EmptyImage` 设置目标宽高，推荐 32 的倍数；这里 batch_size 保持 1，它只做目标尺寸画布。
2. ② 上传主要宣传素材，这是必需输入。其他 8 个素材节点选填，使用时把 IMAGE 输出接到③的 `images.image_3`～`images.image_10`。在提示词里写清每张素材用途。`image_1` 是空白画布，`image_2` 才是主要素材。
3. ③ 正向提示词底部填写目标语言、选填风格、视觉要求和 `<copy>` 内完整上图原文。不要把说明标签也填进 `<copy>`。不要保留空白文案直接运行。
4. ④ `RepeatLatentBatch.amount` 填 1、2、3 或 4。⑤只运行一次采样，一次任务批量出图。原生控件本身允许更大的值，业务范围由你控制为 1–4。
5. ③ `resolution` 保持 0，输出跟随①尺寸；非 32 倍数会按原生编码器规则取整。不要接原来的四通道 `EmptyLatentImage`，也不要用按 8 倍计算尺寸的 `LatentUpscale`。
6. PNG 保存到 ComfyUI/output，前缀 `Qwen_Promo`。不满意直接重新运行，种子设为 randomize。

保留原工作流的三个模型名：
- diffusion_models/qwen_image_2.1_bf16.safetensors
- text_encoders/qwen3vl_8b_int8_convrot.safetensors
- vae/qwen_image_2.1_vae_bf16.safetensors

需要本身支持原生 `TextEncodeQwenImage21` 的 ComfyUI 版本。没有第三方提示词接口、LoRA、Set/Get 或新增 Python 节点。resolution=0 会保留参考图分辨率，参考素材过大、多图和 batch=4 都会增加显存占用。

本版由 Qwen 直接做背景、构图与上字。原文保留、字体风格、无溢出和主体保真写入提示词，由你看图验收。纯模型不保证零错字，不能靠提示词实现严格的缺文案/超长/语言/风格冲突拒绝；这类前置校验、业务结构化返回和部分成功统计由调用方处理。本版只有 ComfyUI 原生图片及执行历史输出，不声称已经具备全部接口验收逻辑。缺少主要素材或文件不可读会由连接着的 LoadImage 报错；不要断开这条必需素材连接。

附带 API 格式 JSON 供接口调用：先上传素材并填 `10.inputs.image`，填 `5.inputs.prompt`，`6.inputs.amount` 控制数量。额外素材可增加 LoadImage 并连接 `images.image_3` 等输入。一次 POST /prompt 提交整个图即可。

仅检查了 JSON/连线与官方节点接口，未运行 GPU 实图。
